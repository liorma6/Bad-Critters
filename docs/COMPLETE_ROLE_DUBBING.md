# One consistent voice per character

Update, 2026-10-01: recording and saving are free; playing with complete personal roles requires the one-time Paid purchase described in [DEPLOYMENT.md](DEPLOYMENT.md#paid-personal-dubbing). The additional all-character option records every role in the selected case, including the narrator, and validates every role before casting them together. The narrator is therefore no longer creator-only in that option. Creator-voiced play is free. The historical checks below describe the earlier single-role release; current purchase and multi-role checks live in `tests/dubbing-access.test.mjs` and `tests/browser/purchase.spec.mjs`.

This revision supersedes signature-only personal dubbing and mixed personal/creator fallback for the selected character. It preserves the microphone implementation and its diagnostics, input selector, quiet-level meter, optional enhancement, decoded signal checks and safe cleanup.

At every new case or replay, casting starts unselected: creator voices for everyone, the complete five-line supporting part, or one complete 13-line principal part. Saved recordings can be reused, but the player explicitly confirms this case's choice. New case casting never inherits the preceding character. The guide is creator-only.

The recording session displays complete totals, compatible recordings, new recordings, pending reviews, and a duration estimate based on actual word count, speaking/review time and per-line overhead. Four-line sections make longer parts manageable. A valid stopped take automatically becomes an IndexedDB draft; playback and approval complete its review. Exit and reload restore the saved line position. Missing or unchecked lines block personal activation; the player can continue the draft or start with the creator voicing the entire character.

`VoiceStore` keeps line blobs separately from case/character set manifests. Set requirements include stable line IDs, script versions, text fingerprints and intended performance contexts. Validation and review state are stored per recording. Old signature takes migrate only for explicitly unchanged scripts and only after successful signal decoding. Revised supporting introductions invalidate their old versions. Immediately before personal casting is accepted, the entire role is decoded and checked again.

All game speech uses finite named events in `dialogue-manifest.js`. `AudioManager.configureCase` enforces complete coverage, and playback rejects lines outside the active case manifest. The chosen character uses its personal recording for every reachable event, including world encounters, close-ups, accusation responses and reconstruction. Missing or failed personal media produces the exact subtitle and a deferred repair action; it never requests a creator replacement. Other characters retain normal creator-to-subtitle behavior. Casting cannot change mid-case through the repair screen. A repair can be left unfinished while the same character continues in subtitles.

Local storage uses the existing origin and database, upgraded to schema 2 with a `sets` store. `progress.caseCasting` records the explicit current-case choice, set ID and required fingerprints. It is not automatically applied at the next pre-case screen. No recording or diagnostic is uploaded. Creator recordings are still absent in this source checkout; missing creator audio remains a normal subtitle fallback.

See [DIALOGUE_COVERAGE.md](DIALOGUE_COVERAGE.md) for the before/after audit and every role's count. See `complete-role-test-summary.json` for final verification outcomes. Browser audio fixtures are synthetic and do not claim new physical-microphone verification.
